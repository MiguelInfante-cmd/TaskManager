Resumen Ejecutivo:

El presente informe documenta el diseño y desarrollo de una aplicación web offline-first para la gestión de tareas (TaskManager). La solución fue elaborada en JavaScript Vanilla sin dependencias externas, cumpliendo con operaciones CRUD completas, validación estricta de campos vacíos, consumo asíncrono con control de duplicados desde la API REST de JSONPlaceholder, filtros de estado dinámicos, ordenamiento multidimensional mediante funciones comparadoras y reactividad visual en tiempo real en el dashboard de métricas.

1. Investigación: Arquitectura Modular ES6 (Opción A)

Para garantizar la mantenibilidad, escalabilidad y separación de responsabilidades exigidas en el software moderno, se investigó e implementó la Arquitectura Modular nativa de ECMAScript 6 (ES6 Modules) empleando las sentencias import y export sobre el navegador sin requerir empaquetadores como Webpack o Vite.

1.1 Descomposición y Responsabilidad de Módulos

Módulo Archivo Responsabilidad Principal
Storage Service js/storageService.js Abstracción de localStorage, serialización/deserialización JSON y manejo de excepciones de cuota.
API Service js/apiService.js Consumo asíncrono mediante fetch() y async/await desde JSONPlaceholder, normalización y detección de red.
Task Manager js/taskManager.js Lógica de negocio, CRUD estricto, algoritmos de filtrado, cálculo de métricas y ordenamiento con sort().
UI Service js/ui.js Manipulación limpia del DOM, renderizado reactivo, modales accesibles y notificaciones contextuales Toast.
Event Bus js/events.js Desacoplamiento mediante CustomEvent para comunicación reactiva entre capas.

2. Patrón Observador con Custom Events (Opción B Integrada)

Como valor agregado a la arquitectura, se implementó el Patrón Observador utilizando la API nativa CustomEvent de JavaScript. Cuando cualquier operación modifica el estado de las tareas (creación, edición, borrado o sincronización), el gestor emite el evento personalizado taskmanager:tasksUpdated con el detalle de las métricas. El módulo visual escucha este evento y re-renderiza el Dashboard y la barra de progreso automáticamente, evitando el acoplamiento directo entre la lógica de negocio y la interfaz.

3. Mecanismos Algorítmicos: Validación, Filtros y Ordenamiento

  • Validación Estricta: Se intercepta el evento submit del formulario y el evento input. Se evalúa title.trim().length >= 3. Si el campo está vacío, se aplica retroalimentación visual con bordes rojos y alertas inline antes de permitir cualquier mutación.
  • Búsqueda en Tiempo Real: Se implementó búsqueda dinámica insensible a mayúsculas utilizando toLowerCase() e includes(), ejecutada en cada pulsación de tecla sobre el elemento <input id="searchInput">.
  • Ordenamiento Multidimensional con sort(): Se programó una función comparadora personalizada que maneja pesos de prioridad (Alta: 3, Media: 2, Baja: 1) con un desempate cronológico secundario basado en createdAt.

6. Conclusiones

1. Solidez de JavaScript Vanilla: Se comprobó que el estándar moderno de JavaScript (ES6+) cuenta con todas las herramientas nativas necesarias (módulos, manipulación del DOM, eventos personalizados y API Fetch) para desarrollar sistemas complejos sin sobrecargar el navegador con dependencias externas.

2. Estrategia Offline-First: El uso disciplinado de Web Storage API combinado con detección de eventos de red permite brindar una experiencia de usuario fluida y resiliente, eliminando la dependencia crítica de la conexión a internet para la operatividad básica.

3. Buenas Prácticas en el Control de Versiones: El desarrollo estructurado por fases y respaldado por un historial de commits significativo en GitHub garantiza la autoría real del código y la transparencia metodológica en la integración de Inteligencia Artificial como herramienta de apoyo.
